# Observatory UI/UX Requirements - Extracted from Specification

## DASHBOARD & MAIN VIEWS

### Primary Dashboard Output
- Observatory Dashboard: Main interface for users to view priority scores and recommendations
- Continuously updated priority score for product development
- Answers two core questions every sprint cycle:
  1. What is the highest-impact thing we could build or change right now?
  2. What is the evidence behind that recommendation?
- Displays data from five input layers
- Shows decision traceability and evidence sources

## USER WORKFLOWS & INTERACTION PATTERNS

### Head of Product Workflow (Weekly)
- Input: Logs in weekly
- Views/Screens:
  - Feature friction reports
  - Experiment recommendations (ranked by expected revenue impact)
  - Competitor feature changes
- Key Component: "Top 3 Experiments to Run" Section
  - Ranked by expected revenue impact
  - Hypothesis statements ready for engineering
  - Variant descriptions included
  - Experiment specs with A/B test designs
  - Expected impact clearly stated

### Head of Marketing Workflow (Weekly)
- Input: Logs in weekly
- Views/Screens:
  - Competitive messaging shifts data
  - Sentiment trends visualization
  - Battlecard updates

### Research Lead Workflow (As Needed)
- Input: Logs in as needed
- Views/Screens:
  - Research gap briefs with cost estimates
  - Research gap briefs with value estimates

### CEO/MD Workflow (Monthly)
- Input: Receives monthly digest
- Views/Screens:
  - Strategic overview section
  - Biggest competitive shifts
  - Top insights
  - Portfolio trends

### Sales Team Workflow (Weekly)
- Input: Receives weekly battlecards
- Views/Screens:
  - Updated competitive positioning
  - Key differentiators
  - Feature comparison data

### Engineering Leads Workflow
- Input: Receives experiment specs
- Views/Screens:
  - A/B test designs with hypothesis, variants, expected impact

2. Internal Product Telemetry Layer
   - User drop-off points in key flows
   - Feature usage patterns
   - Churn prediction patterns

3. Voice of Customer Layer
   - Support ticket themes
   - Live chat complaints
   - App store review sentiment
   - User requests tracking

4. Historic Knowledge Layer
   - Past research findings
   - Knowledge base content
   - Past surveys data

5. Targeted Primary Research Layer
   - Research gaps identified
   - Research briefs with estimated costs
   - Commissioned research status

- Display Must Show:
  - Where users leave (flow visualization)
  - Why users leave (VoC data, app store review themes)
  - What to do about it (recommended actions)
  - Revenue impact quantification

- Hypothesis statements
- Variant descriptions
- Expected impact estimates in revenue terms
- Ranking by expected revenue impact

- Interventions recommended

- Strategic overview

## DESIGN PRINCIPLES

1. Speed & Velocity First - Quick scan-friendly, summary-then-detail, one-click evidence
2. Evidence Transparency - Sources visible, limitations noted, confidence indicators
3. Action Orientation - Clear CTAs, ready-to-use recommendations, team-specific formats
4. Decision Support - Recommendations marked as suggestions, evidence-based, alternative perspectives
5. Integration-First - Embedded in workflows, seamless data combination, tool-matched output
